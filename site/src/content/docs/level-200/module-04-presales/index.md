This module prepares architects and solutions professionals for pre-sales work on Microsoft Sovereign Cloud opportunities. You will turn discovery answers into a deployment model, design scope, sizing assumptions, and cost model.

Microsoft Sovereign Cloud has three deployment models: [Sovereign Public Cloud](https://learn.microsoft.com/azure/azure-sovereign-clouds/public/overview-sovereign-public-cloud), [Sovereign Private Cloud](https://learn.microsoft.com/azure/azure-sovereign-clouds/private/overview/sovereign-private-cloud), and [National Partner Clouds](https://learn.microsoft.com/azure/azure-sovereign-clouds/partner/overview-national-partner-clouds). Pre-sales work starts by proving which model fits the customer's law, regulator, operations model, connectivity, and workload needs.

## Before you start

Bring three inputs into each customer session:

- A list of regulated data types, data locations, and control owners.
- Current workload facts, including users, applications, recovery targets, data growth, and connected or disconnected operations needs.
- Commercial constraints, including hardware refresh timing, Azure subscription model, existing Windows Server licensing, and support plan.

Avoid generic "sovereign by design" claims. State the mechanism instead, such as where the control plane runs, who operates it, which workloads are supported, and which billing model applies.
