The Microsoft Learn fundamentals path groups the benefits of cloud services into five areas: availability and scalability, reliability and predictability, security and governance, manageability, and sustainability. Each benefit has a cost or a condition, so this page covers both.

<LearningObjectives>
- Explain high availability, scalability, reliability, and predictability.
- Tell vertical scaling from horizontal scaling.
- Describe how the cloud helps with governance and manageability.
- List the trade-offs to plan for before you move a workload.
</LearningObjectives>

## High availability

**High availability** means a resource is available when people need it, despite disruptions. Cloud providers state availability guarantees per service in a service-level agreement (SLA). Each Azure service has its own SLA, so check the SLA for every service in your design rather than assuming one number for the whole solution.

## Scalability

**Scalability** is the ability to adjust resources to meet demand. Because you pay for what you use, scaling down when demand drops also lowers your bill.

There are two ways to scale:

- **Vertical scaling** changes the size of a resource. You scale up by adding CPUs or memory to a VM, and scale down by removing them.
- **Horizontal scaling** changes the number of resources. You scale out by adding VMs or containers, and scale in by removing them. Horizontal scaling can be manual or automatic.

## Reliability

**Reliability** is the ability of a system to recover from failures and keep working. It's one of the pillars of the Azure Well-Architected Framework. Cloud providers run datacenters in many regions, so you can design an application that keeps running in another region if one region has a major outage. Module 3 explains Azure regions and availability zones.

## Predictability

Predictability has two parts:

- **Performance predictability.** Autoscaling adds resources when demand rises. Load balancing spreads traffic so no single resource is overloaded.
- **Cost predictability.** You can track resource use in real time, find patterns, and forecast spend. Before you deploy, the Azure Pricing Calculator estimates what a design will cost.

## Security and governance

Templates and policies help you deploy resources that meet your technical standards and regulatory requirements, and update them at scale when the standards change. Cloud auditing flags resources that drift from your baseline. Depending on the service model, the provider applies operating system patches for you.

You choose how much security work to keep. IaaS gives you the most control and the most patching. PaaS and SaaS hand patching and maintenance to the provider. Providers also operate defenses at a scale most organizations can't, such as protection against distributed denial-of-service (DDoS) attacks.

## Manageability

Microsoft Learn splits manageability into two parts.

Management **of** the cloud is what the platform can do to your resources:

- Scale them automatically based on demand.
- Deploy them from a template, without manual configuration.
- Monitor their health and replace failing resources.
- Send alerts when a metric crosses a threshold.

Management **in** the cloud is how you work with the platform: through a web portal, a command-line interface, APIs, or PowerShell. Module 3 covers the Azure versions of these tools.

## Sustainability

Cloud providers run at large scale, which can use hardware more efficiently than many separate on-premises server rooms. You only get that benefit if you run lean:

- Scale resources down when demand drops.
- Shut down or deallocate resources you aren't using. For example, stop a development environment overnight and at weekends.
- Pick services and sizes that match the workload instead of overprovisioning.
- Track usage over time and adjust.

## Trade-offs to plan for

| Area | What to plan for |
|---|---|
| Cost control | Pay-as-you-go cuts idle hardware, but forgotten resources keep billing. Set budgets and alerts, and review usage. |
| Data location and control | Your data runs in the provider's datacenters. Choose regions that meet your legal and contractual requirements, and understand who operates the platform. |
| Connectivity | Cloud services assume a reliable network link. Sites with poor connectivity need local compute. |
| Skills | Cloud architecture, automation, and cloud security need training. Teams also change how they work. |
| Portability | Higher-level services save effort but are specific to one provider. Moving later takes more work. |

Data location and control are the subject of this course. Level 100 explains how Microsoft Sovereign Cloud answers them.
