## What cloud computing is

Cloud computing is the delivery of computing services over the internet. The services include common IT infrastructure such as virtual machines, storage, databases, and networking. They also include higher-level services such as Internet of Things (IoT), machine learning, and AI.

Because the services come over a network, you don't wait for hardware to arrive before you can use them. A retail team that expects a traffic spike for a seasonal launch can add compute capacity for the launch week and remove it afterward, instead of buying servers months in advance.

## The five essential characteristics

The US National Institute of Standards and Technology (NIST) defines cloud computing in Special Publication 800-145. Microsoft Learn uses the same publication for the service model definitions (IaaS, PaaS, SaaS) that you meet on the next page. NIST lists five characteristics that every cloud service has.

| Characteristic | What it means in practice |
|---|---|
| On-demand self-service | You create and delete resources yourself, through a portal or an API, without a ticket to the provider. |
| Broad network access | You reach the service over the network from laptops, phones, servers, and scripts using standard protocols. |
| Resource pooling | The provider runs one large pool of hardware and assigns parts of it to many customers (tenants). You usually don't know or choose the exact server. |
| Rapid elasticity | You add capacity when demand rises and release it when demand falls, often automatically. |
| Measured service | The provider meters what you use (compute hours, gigabytes stored, requests) and bills you for it. |

Resource pooling is the characteristic that raises the most questions later in this course. If many tenants share hardware, you need to know where that hardware is, who operates it, and how your data is kept separate. Those questions are the starting point for digital sovereignty in Level 100.

## Virtualization makes the pool possible

A **hypervisor** is software that runs several virtual machines (VMs) on one physical server. Each VM gets its own share of CPU, memory, storage, and network, and runs its own operating system. The hypervisor keeps the VMs isolated from each other.

There are two kinds of hypervisor:

- A **type 1** (bare-metal) hypervisor runs directly on the server hardware. Datacenters and clouds use this kind. Hyper-V uses a type 1 hypervisor architecture.
- A **type 2** (hosted) hypervisor runs as an application on top of a desktop operating system. Developers use this kind to run a test VM on a laptop.

The Azure hypervisor is based on Windows Hyper-V. It runs each VM in a separate guest partition with its own address space, and enforces the security boundary between them.

## From buying hardware to paying for use

Cloud computing uses a **consumption-based model**. You pay for the IT resources you use and release them when you're done.

Traditional IT budgets split spending into two kinds:

- **Capital expenditure (CapEx)** is up-front spending on physical things: servers, network hardware, and datacenter space. You pay before you use them, and you pay the same whether they're busy or idle.
- **Operational expenditure (OpEx)** is ongoing spending on services over time. Because you pay for cloud services as you consume them, cloud computing is an operational expense.

The difference shows up in capacity planning. With your own datacenter, you estimate demand in advance. If you overestimate, servers sit idle. If you underestimate, applications slow down until you order, install, and power more hardware. In the cloud you add VMs when demand rises and remove them when it drops.

## Questions the cloud raises

The same features that make the cloud flexible create questions you answer during design:

- Data location. Resource pooling means your data sits in the provider's datacenters. You choose the region, and regulations may limit which regions you can use.
- Operator access. The provider runs the hardware and the platform. You need to know who can access the systems that hold your data, and under which rules.
- Connectivity. Broad network access assumes a network. Sites with poor or no connectivity need a different design.

Microsoft Sovereign Cloud addresses these questions with three deployment models: Sovereign Public Cloud, Sovereign Private Cloud, and National Partner Clouds ([Microsoft Learn](https://learn.microsoft.com/azure/azure-sovereign-clouds/microsoft-sovereign-cloud)).
