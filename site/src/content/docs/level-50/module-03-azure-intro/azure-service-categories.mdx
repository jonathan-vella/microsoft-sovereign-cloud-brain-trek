Azure has hundreds of services. You don't need to know them all. The Azure Fundamentals learning path on Microsoft Learn focuses on four core categories: compute, networking, storage, and identity and security. This page covers those four in more depth and gives a short view of the rest.

## Compute

Compute services run your code. They range from full control to fully managed.

| Service | Model | Use it when |
|---|---|---|
| Azure Virtual Machines | IaaS | You need full control of the operating system, or you're moving an existing server as is. |
| Virtual Machine Scale Sets | IaaS | You need many identical VMs that scale in and out together. |
| Azure Virtual Desktop | Desktop virtualization | Users need Windows desktops and apps delivered from the cloud. |
| Azure Container Instances | PaaS | You want to run a container quickly, without managing VMs. |
| Azure Container Apps | PaaS | You run containerized apps that need built-in load balancing and scaling. |
| Azure Kubernetes Service (AKS) | Managed orchestration | You run a fleet of containers and want Kubernetes to manage them. |
| Azure Functions | Serverless | Code runs in response to an event, such as a message or an HTTP request, with no servers to manage. |
| Azure App Service | PaaS | You host web apps and APIs without managing servers. |

A **container** packages an application with what it needs to run. Many containers can share one host, and they start and stop faster than VMs. Unlike a VM, you don't manage an operating system for each container.

## Networking

- An **Azure virtual network (VNet)** is your private network in Azure. Resources in a VNet talk to each other privately. You split a VNet into subnets and filter traffic with network security groups.
- **VPN Gateway** connects an on-premises network to a VNet with an encrypted tunnel over the internet.
- **ExpressRoute** connects your offices and datacenters to the Microsoft cloud over a private connection through a connectivity provider. The traffic doesn't cross the public internet, which gives more consistent latency and higher security.
- **Azure DNS** hosts your domain names on Microsoft's infrastructure.

## Storage

An Azure **storage account** holds your data. Azure encrypts all data written to a storage account. Azure Storage has five core services:

| Service | What it stores |
|---|---|
| Azure Blobs | Objects: documents, images, video, backups, and data for analytics |
| Azure Files | File shares that you mount over SMB or NFS from the cloud or on-premises |
| Azure Queues | Messages passed between parts of an application |
| Azure Disks | Block storage volumes (managed disks) for VMs |
| Azure Tables | Structured, non-relational (NoSQL) data |

### Access tiers

Blob storage has access tiers that trade storage cost against access cost.

| Tier | Best for | Minimum storage period |
|---|---|---|
| Hot | Data in active use | None |
| Cool | Infrequently accessed data that must be available immediately | 30 days |
| Cold | Rarely accessed data that must be available immediately | 90 days |
| Archive | Rarely accessed data that can wait hours to be read back | 180 days |

If you delete or move a blob before its tier's minimum period, you pay an early deletion charge ([Microsoft Learn](https://learn.microsoft.com/azure/storage/blobs/access-tiers-overview)).

### Redundancy

Azure Storage always keeps three copies of your data in the primary region. You choose how far apart they are:

| Option | Where the copies are |
|---|---|
| Locally redundant storage (LRS) | Three copies in one datacenter |
| Zone-redundant storage (ZRS) | One copy in each of three availability zones in the region |
| Geo-redundant storage (GRS) | LRS in the primary region, plus LRS in a paired secondary region |
| Geo-zone-redundant storage (GZRS) | ZRS in the primary region, plus LRS in a paired secondary region |

Microsoft recommends ZRS when data must stay inside one country or region, because it doesn't copy data to a second region ([Microsoft Learn](https://learn.microsoft.com/training/modules/describe-azure-storage-services/3-redundancy)).

## Databases

Azure runs managed databases, so Microsoft handles patching, backups, and high availability:

- **Azure SQL Database** for relational data on the SQL Server engine.
- **Azure Cosmos DB** for NoSQL data that needs global distribution.
- **Azure Database for PostgreSQL** and **Azure Database for MySQL** for open-source relational databases.

## Identity and security

Module 2 covered these in detail:

- **Microsoft Entra ID** authenticates users and applications and enforces Conditional Access.
- **Azure Key Vault** stores secrets, encryption keys, and certificates.
- **Microsoft Defender for Cloud** assesses your security posture and protects workloads in Azure, other clouds, and on-premises. Microsoft is moving its experience into the unified Microsoft Defender portal ([Microsoft Learn](https://learn.microsoft.com/azure/defender-for-cloud/defender-for-cloud-introduction)).

## AI and machine learning

The names of the Azure AI services changed recently. Older material uses the earlier names.

| Current name | Earlier name | What it does |
|---|---|---|
| Microsoft Foundry | Azure AI Studio, then Azure AI Foundry | One platform for building AI agents and applications, with a catalog of models from Microsoft, OpenAI, and others |
| Foundry Tools | Azure AI services | Prebuilt APIs for language, speech, vision, and document processing |
| Azure Machine Learning | Same | Build, train, and manage your own machine learning models |

Source: [What is Microsoft Foundry?](https://learn.microsoft.com/azure/foundry/what-is-foundry)

Level 100 introduces **Foundry Local**, which runs AI models on your own hardware with Azure Local. It's in preview ([Microsoft Learn](https://learn.microsoft.com/azure/azure-sovereign-clouds/private/foundry-local/overview)).

## Other categories

- **Analytics.** Azure Data Factory moves and transforms data. Azure Databricks and Azure Stream Analytics process it.
- **Integration.** Logic Apps automates workflows. API Management publishes APIs. Service Bus passes messages between applications.
- **Internet of Things.** IoT Hub connects and manages devices. IoT Edge runs cloud workloads on devices near where data is created.
- **Management and governance.** Azure Monitor collects metrics and logs. Azure Policy enforces rules on resources. Azure Arc extends Azure management to resources outside Azure.
