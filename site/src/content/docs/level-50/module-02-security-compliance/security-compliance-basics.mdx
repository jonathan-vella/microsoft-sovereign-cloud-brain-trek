Security protects data and systems from threats. Compliance proves that you meet the rules that apply to you. This page covers the security models that the rest of the course builds on. The next pages go deeper into data protection, compliance frameworks, and identity.

## The CIA triad

Every security control protects at least one of three properties. Together they're called the **CIA triad**.

| Property | Meaning | Example controls | What an attack on it looks like |
|---|---|---|---|
| Confidentiality | Only authorized people can read the data. | Encryption, access control, secure transmission | A data breach exposes customer records. |
| Integrity | Data stays accurate and complete, and changes only through authorized processes. | Hashing, digital signatures, audit logs, database transactions | An attacker edits payment details, or deletes records. |
| Availability | Authorized users can reach data and systems when they need them. | Redundancy, load balancing, failover, tested backups, DDoS protection | Ransomware encrypts files, or a flood of traffic takes a site offline. |

The three properties can pull against each other. Strong encryption protects confidentiality, but if you lose the keys, the data is gone for good, which hurts availability. Security teams balance them based on how sensitive the data is and what the business needs.

## Defense in depth

A **defense-in-depth** strategy layers several controls around the data, instead of relying on one perimeter. If an attacker gets through one layer, the next one still stands. Each layer slows the attacker down and gives defenders another chance to detect the attack.

Microsoft Learn describes seven layers, from the outside in:

1. **Physical security.** Locked buildings, guards, badge readers, and cameras control who can touch the hardware.
2. **Identity and access.** Multifactor authentication, role-based access control, and Conditional Access check who is signing in and what they may do. Sign-ins and changes are logged.
3. **Perimeter.** Distributed denial-of-service (DDoS) protection filters large-scale attacks, and perimeter firewalls inspect traffic entering and leaving the network.
4. **Network.** Segmentation and network security groups limit which resources can talk to each other. The rule is deny by default.
5. **Compute.** Virtual machines and containers are patched, have endpoint protection, and expose only the ports and admin access they need.
6. **Application.** Applications are built securely, tested for vulnerabilities, and keep their secrets in a vault such as Azure Key Vault instead of in code.
7. **Data.** Access control, encryption at rest and in transit, and classification protect the data itself. Data is what attackers are after.

In the cloud, the shared responsibility model decides who runs each layer. The provider runs physical security for every service model. You always own identity and access for your users, and the data layer.

## Zero Trust

Traditional security assumed that anything inside the corporate network was safe. That stopped working once people worked from anywhere and data moved to cloud services. Attackers now get in with phishing and stolen credentials, then move around inside.

**Zero Trust** is a security strategy, not a product. Its short form is "never trust, always verify." Every access request is treated as untrusted, wherever it comes from.

### Three principles

| Principle | What it means |
|---|---|
| Verify explicitly | Authenticate and authorize every request using all available signals: identity, location, device health, the app or data requested, and unusual behavior. |
| Use least privilege access | Give users and workloads only the access they need, for the shortest time. Just-in-time and just-enough access put this into practice. |
| Assume breach | Design as if an attacker is already inside. Segment access, encrypt end to end, and monitor so you detect and contain an attack quickly. |

### Seven technology pillars

Microsoft's Zero Trust guidance applies the principles across seven technology pillars ([Microsoft Learn](https://learn.microsoft.com/security/zero-trust/deploy/overview)). Older material lists six. The seventh pillar, security operations, now stands on its own.

| Pillar | What it covers |
|---|---|
| Identities | Verify every user, service, and device, and enforce least privilege. |
| Endpoints | Decide access based on device health, compliance, and risk. |
| Data | Classify, label, and encrypt data so protection travels with it. |
| Apps | Control how apps and APIs reach data, including permissions and session controls. |
| Infrastructure | Harden and monitor servers, VMs, containers, and services. |
| Network | Segment and monitor traffic to stop lateral movement. |
| SecOps | Collect signals from all the other pillars to detect, investigate, and respond. |

The Microsoft Learn security fundamentals module uses slightly different names for two pillars: devices for endpoints, and visibility, automation, and orchestration for SecOps. They describe the same areas.

The pillars sit in a four-layer adoption model: business scenarios (why), security disciplines (what), technology pillars (where), and technical solutions (how).

## Governance, risk, and compliance

Governance, risk, and compliance (GRC) are related practices that are easy to mix up.

- **Governance** is the set of rules and processes an organization uses to direct its work. Examples: who may access which resources, who gets admin rights and for how long, and how data must be classified.
- **Risk management** finds and handles threats to the organization. The usual cycle is identify, assess (impact and likelihood), respond, and monitor. You can respond to a risk in four ways: accept it, mitigate it with controls, transfer it (for example, with insurance), or avoid it by changing the process.
- **Compliance** is meeting the laws, regulations, and standards that apply because of your industry, location, and data.

Compliance isn't the same as security. Compliance sets the minimum that rules require. An organization can pass an audit and still have serious security gaps.
