Data is the innermost layer of defense in depth and the target of most attacks. This page covers the basic ways to protect it: know what you have, encrypt it, control the keys, stop it from leaking, and handle personal data with care.

## Classify data first

You can't protect everything at the highest level, and you shouldn't try. **Data classification** sorts data by how much harm its exposure would cause, so each class gets the right controls.

Many organizations use four or five levels. A common vendor-neutral scheme:

| Level | Harm if disclosed | Examples | Typical controls |
|---|---|---|---|
| Public | None | Press releases, published prices | Integrity checks only |
| Internal | Minor | Policies, internal procedures | Sign-in required |
| Confidential | Serious | Financial results, HR records, contracts | Restricted access, encryption |
| Restricted | Severe | Personal data, credentials, trade secrets | Strict access, encryption, monitoring, data loss prevention |

In Microsoft 365 and Azure, Microsoft Purview applies classification with **sensitivity labels**. A label can add encryption, access restrictions, and visual markings, and the protection travels with the file or email wherever it goes.

## Encryption

**Encryption** makes data unreadable without a secret key. If an attacker steals encrypted data but not the key, the data is useless to them.

### Two kinds of encryption

- **Symmetric** encryption uses the same key to encrypt and decrypt. It's fast, so it's used for large amounts of data such as disks and databases. The hard part is sharing the key safely.
- **Asymmetric** encryption uses a key pair. Anyone can encrypt with the public key, and only the holder of the private key can decrypt. HTTPS uses it to set up secure connections. The private key can also create **digital signatures** that prove who sent the data and that it wasn't changed.

### Three states of data

| State | What it means | How it's protected |
|---|---|---|
| At rest | Stored on a disk, in a database, or in a storage account | Storage and database encryption |
| In transit | Moving across a network, between services, or to a user | Transport Layer Security (TLS) for HTTPS, and VPN tunnels |
| In use | Loaded into memory and being processed | Confidential computing, which processes data in a protected hardware environment that the operating system and hypervisor can't read |

Encryption in use matters most in shared, multitenant environments, where other customers' workloads run on the same physical hardware. Level 200 covers confidential computing in Azure.

### Hashing is not encryption

**Hashing** turns any input into a fixed-length value. Unlike encryption, it's one-way: you can't get the original back from the hash. Systems store password hashes instead of passwords, and add a random **salt** to each password before hashing so that identical passwords give different hashes. Hashing also checks integrity: if a file's hash matches the published value, the file wasn't changed.

## Key management

Encryption is only as strong as the protection of its keys. Good key management means:

- Store keys separately from the data they protect.
- Keep high-value keys in a **hardware security module (HSM)**, a tamper-resistant device built to store keys.
- Rotate keys on a schedule, so a leaked key exposes less data.
- Limit who can use, view, and rotate keys, and audit their use.

In Azure, **Azure Key Vault** stores and controls access to secrets (such as connection strings and passwords), encryption keys, and certificates. Applications fetch secrets from Key Vault at runtime instead of keeping them in code. Who holds the keys is a central sovereignty question, and Level 100 returns to it.

## Data loss prevention

**Data loss prevention (DLP)** stops sensitive data from leaving where it should be. A DLP policy watches for sensitive information, such as card numbers or files with a Confidential label, and warns the user, blocks the action, or alerts an administrator. Microsoft Purview DLP works across Microsoft 365 services and endpoints.

## Backups protect availability

Encryption protects confidentiality, but it doesn't help if ransomware encrypts your files or someone deletes a database. Regular, tested backups stored away from the original data protect availability and integrity.

## Privacy principles

Privacy is about handling **personal data**: anything that relates to an identified or identifiable person, from names and email addresses to location history. Privacy laws, such as the EU General Data Protection Regulation (GDPR), generally require you to:

- Tell people what personal data you collect and how you use it.
- Get consent before you collect certain categories of data.
- Give people rights over their data, such as access, correction, and deletion.
- Protect personal data against unauthorized access.

Microsoft's GDPR accountability readiness checklists add privacy by design and by default. That includes **minimization**: collect, process, and keep only the personal data you need.

## Data residency and data sovereignty

Two terms come up in every sovereignty conversation:

- **Data residency** is about where data is physically stored, and when it may be moved, processed, or accessed across borders.
- **Data sovereignty** means data is subject to the laws of the country where it's collected, held, or processed. One record collected in one country, stored in a second, and processed in a third can fall under all three sets of laws.

Data residency is a location. Data sovereignty is about which laws apply and who controls access. Level 100 builds on this distinction.
