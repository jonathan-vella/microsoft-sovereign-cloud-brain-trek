### Question 1: Sovereignty dimensions

Which set matches the digital sovereignty dimensions named in this module?

- A) Compute, storage, and networking
- B) Data controls, operational controls, and technological independence
- C) Public cloud, private cloud, and hybrid cloud
- D) GDPR, NIS2, and DORA

<KnowledgeCheck answer="B" reference="/level-100/module-01-digital-sovereignty/digital-sovereignty/">

B is correct because Microsoft Learn names technological independence as a dimension of digital sovereignty alongside data controls and operational controls. A lists infrastructure categories, not sovereignty dimensions. C lists deployment patterns that are covered in the next module. D lists regulations and does not define the sovereignty dimensions.

</KnowledgeCheck>

### Question 2: Residency and sovereignty

A customer asks where its database files and backups are stored. Which concept does that question primarily test?

- A) Data residency
- B) Data sovereignty
- C) Technological independence
- D) Operational sovereignty

<KnowledgeCheck answer="A" reference="/level-100/module-01-digital-sovereignty/data-residency-concepts/">

A is correct because data residency focuses on the physical or geographic location where data is stored. B is broader and includes legal authority, governance, and access. C concerns choice and control over infrastructure and technology. D concerns who can operate and access the environment.

</KnowledgeCheck>

### Question 3: Data localization

What makes data localization different from data residency?

- A) Data localization is a legal or policy mandate to keep data in a place.
- B) Data localization means data is encrypted in memory.
- C) Data localization applies only to Microsoft 365 tenants.
- D) Data localization means Microsoft support cannot access data.

<KnowledgeCheck answer="A" reference="/level-100/module-01-digital-sovereignty/data-residency-concepts/">

A is correct because data localization is a requirement imposed by law or policy. B describes confidential computing. C is too narrow and confuses localization with one product's scope rules. D describes an access-control concern, not localization.

</KnowledgeCheck>

### Question 4: European digital commitments

Which item is one of Microsoft's five European digital commitments announced on April 30, 2025?

- A) Retire Azure public cloud regions outside Europe.
- B) Always help protect and defend Europe's cybersecurity.
- C) Require every European customer to use Multi-Geo.
- D) Replace GDPR with the EU Data Boundary.

<KnowledgeCheck answer="B" reference="/level-100/module-01-digital-sovereignty/european-commitments/">

B is correct because Microsoft Learn lists "Always help protect and defend Europe's cybersecurity" as one of the five commitments. A is not a Microsoft commitment. C is wrong because Microsoft 365 Multi-Geo customers are not in scope for the EU Data Boundary. D is wrong because the EU Data Boundary does not replace GDPR.

</KnowledgeCheck>

### Question 5: EU Data Boundary geography

Which countries are included in the EU Data Boundary geography?

- A) The 27 EU member states plus Iceland, Liechtenstein, Norway, and Switzerland
- B) Only countries that use the euro
- C) The 27 EU member states plus the United Kingdom
- D) Only Azure regions inside the European Union

<KnowledgeCheck answer="A" reference="/level-100/module-01-digital-sovereignty/european-commitments/">

A is correct because Microsoft defines the boundary as the EU plus the four EFTA countries. B is wrong because euro use is not the scope rule. C is wrong because the United Kingdom is not listed as an EFTA country in the EU Data Boundary. D is wrong because the boundary applies to covered services and countries, not only Azure regions.

</KnowledgeCheck>

### Question 6: EU Data Boundary logs

How does Microsoft describe personal data in system-generated logs under the EU Data Boundary?

- A) It is anonymized, so Microsoft can never reidentify any event.
- B) It is pseudonymized, and controls apply to data that could reidentify individuals.
- C) It is always excluded from the EU Data Boundary.
- D) It is stored only in Microsoft 365.

<KnowledgeCheck answer="B" reference="/level-100/module-01-digital-sovereignty/european-commitments/">

B is correct because Microsoft requires personal data in system-generated logs to be pseudonymized and applies controls to data that could reidentify individuals. A is wrong because the page explicitly contrasts pseudonymization with anonymization. C is wrong because pseudonymized personal data is part of the EU Data Boundary documentation. D is wrong because the documentation covers multiple enterprise online services.

</KnowledgeCheck>

### Question 7: Product-specific EU Data Boundary rules

Which statement about EU Data Boundary scope is correct?

- A) Azure regional services deployed in an EU Data Boundary region are in scope, while Azure non-regional services need separate configuration.
- B) Microsoft 365 Multi-Geo tenants are always in scope if one satellite geography is in the EU.
- C) Dynamics 365 and Power Platform need only an EU billing address.
- D) All covered products use the same tenant sign-up location rule.

<KnowledgeCheck answer="A" reference="/level-100/module-01-digital-sovereignty/european-commitments/">

A is correct because the Azure rule is region-based for regional services, with separate configuration for non-regional services. B is wrong because Microsoft 365 Multi-Geo customers are excluded from the EU Data Boundary scope. C is wrong because Dynamics 365 and Power Platform require both EU or EFTA Macro Region Geography placement and an EU Data Boundary billing address. D is wrong because scope rules differ by product.

</KnowledgeCheck>

### Question 8: Operational access controls

Which control gives customers an approval workflow before eligible Microsoft engineers can access customer data for support?

- A) Sovereign Control Panel
- B) Customer Lockbox
- C) Azure region pairs
- D) Data localization

<KnowledgeCheck answer="B" reference="/level-100/module-01-digital-sovereignty/operational-sovereignty/">

B is correct because Customer Lockbox lets customer approvers approve or reject eligible Microsoft access requests. A provides sovereignty posture management, not the approval workflow itself. C supports resiliency and residency planning but does not approve support access. D is a legal or policy requirement for data location.

</KnowledgeCheck>

### Question 9: Customer-held keys

Which statement about external key management is current?

- A) Managed HSM External Key Management is generally available for all Azure clouds.
- B) Managed HSM key sovereignty is generally available, while Managed HSM External Key Management is in preview.
- C) External Key Management supports all key operations, including sign, verify, encrypt, and decrypt.
- D) External Key Management removes the need for customer-operated HSM availability planning.

<KnowledgeCheck answer="B" reference="/level-100/module-01-digital-sovereignty/operational-sovereignty/">

B is correct. Managed HSM key sovereignty is generally available, and Managed HSM External Key Management is in preview. A is wrong because the external key management preview excludes Azure Government and Azure operated by 21Vianet. C is wrong because the preview supports wrap and unwrap only. D is wrong because the customer or HSM vendor owns the proxy, HSM, networking, availability, and support.

</KnowledgeCheck>

### Question 10: DORA current status

What current DORA fact should architects know from Microsoft Learn?

- A) DORA applies only to non-cloud software vendors.
- B) Microsoft Ireland Operations Limited is identified as a Critical Third-Party Provider under DORA and is subject to ESA oversight.
- C) DORA compliance begins in 2028.
- D) DORA replaced NIS2 for all regulated industries.

<KnowledgeCheck answer="B" reference="/level-100/module-01-digital-sovereignty/regulatory-overview/">

B is correct because Microsoft Learn states that Microsoft Ireland Operations Limited is identified as a Critical Third-Party Provider under DORA and is subject to ESA oversight. A is wrong because DORA covers financial entities and relevant ICT third-party providers. C is wrong because Microsoft Learn states a January 17, 2025 readiness date. D is wrong because DORA and NIS2 are separate regulatory regimes.

</KnowledgeCheck>

### Question 11: NIS2 tooling

Where does Microsoft currently expose NIS2 as a compliance tool or template?

- A) Defender for Cloud as "EU 2022 2555 (NIS2) 2022" and Purview Compliance Manager as a regulation template
- B) Only Azure Copilot
- C) Only Customer Lockbox
- D) Only Azure Local disconnected operations

<KnowledgeCheck answer="A" reference="/level-100/module-01-digital-sovereignty/regulatory-overview/">

A is correct because Microsoft Learn lists the NIS2 standard in Defender for Cloud and the NIS2 Directive in the Compliance Manager regulations list. B, C, and D name products or capabilities that do not provide the NIS2 compliance standard or template described on this page.

</KnowledgeCheck>

### Question 12: EU AI Act tooling

Why does this module avoid EU AI Act phased implementation dates?

- A) Microsoft Learn has no EU AI Act tooling.
- B) The project source rules require Microsoft documentation for volatile legal dates, and the module only verified Microsoft tooling.
- C) The EU AI Act applies only to hardware.
- D) Defender for Cloud cannot list AI standards.

<KnowledgeCheck answer="B" reference="/level-100/module-01-digital-sovereignty/regulatory-overview/">

B is correct because the module verified EU AI Act tooling in Defender for Cloud and Purview Compliance Manager, but did not verify phased implementation dates from a Microsoft source. A is wrong because Microsoft Learn lists EU AI Act tooling. C is wrong because the regulation is not hardware-only. D is wrong because Defender for Cloud lists the EU AI Act as an available regulatory compliance standard.

</KnowledgeCheck>
