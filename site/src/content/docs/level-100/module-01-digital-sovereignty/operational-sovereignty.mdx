## What operational sovereignty asks

Operational sovereignty asks who can operate, support, and access your environment. It is the control dimension that sits next to data residency. A workload can store data in the right region and still need stronger oversight of provider access, key custody, runtime confidentiality, and evidence collection.

Microsoft Learn describes operational controls as a foundation of digital sovereignty because they maintain transparency, accountability, and autonomy over cloud operations and infrastructure. For Level 100, focus on the concepts. Module 2 covers the [Sovereign Public Cloud model](/level-100/module-02-cloud-models/sovereign-public-cloud/) in more product detail.

## Microsoft personnel access

Most Microsoft operations do not require access to customer data. In rare support cases where access is needed, Microsoft provides controls that add customer approval, regional oversight, and audit evidence.

### Customer Lockbox

[Customer Lockbox for Microsoft Azure](https://learn.microsoft.com/azure/security/fundamentals/customer-lockbox-overview) gives eligible customer approvers an interface to approve or reject Microsoft requests for access to customer data. Microsoft uses it when an engineer needs customer data access for a customer-initiated support ticket or a Microsoft-identified problem.

Customer Lockbox for Azure requires at least a [Developer Azure support plan](https://learn.microsoft.com/azure/security/fundamentals/customer-lockbox-overview). Requests wait in a customer approval state and expire if they are not approved. The service writes audit events to Azure activity logs or Microsoft Entra audit logs, depending on request scope.

Customer Lockbox is not a universal access gate. Microsoft documents exclusions for emergency break-glass scenarios and external legal demands.

### Data Guardian

[Data Guardian](https://learn.microsoft.com/azure/azure-sovereign-clouds/public/data-guardian) is a Sovereign Public Cloud feature for enhanced operational oversight. It ensures that Microsoft personnel remote access to systems in defined regions such as EU+EFTA is monitored by authorized European-resident personnel. Microsoft logs those access sessions in a tamper-evident ledger that uses Azure Confidential Ledger.

At Level 100, treat Data Guardian as an oversight and evidence concept. It answers the question, "Who watches Microsoft operational access, and where is the access record kept?"

## Customer-held keys

Key custody is one way to reduce reliance on provider access. Microsoft describes two relevant patterns.

### Managed HSM key sovereignty

[Azure Key Vault Managed HSM key sovereignty](https://learn.microsoft.com/azure/azure-sovereign-clouds/public/external-key-management) is generally available. It gives customers FIPS 140-3 Level 3 validated security, single-tenant isolation, and customer-controlled security domains. For most organizations, Microsoft positions Managed HSM keys as the recommended way to meet stringent key sovereignty requirements.

### Managed HSM External Key Management

[Managed HSM external key management is in preview](https://learn.microsoft.com/azure/key-vault/managed-hsm/external-key-management-overview). It keeps the Key Encryption Key in a customer-owned and customer-operated HSM outside Microsoft infrastructure. Managed HSM delegates wrap and unwrap operations to that external HSM through a customer-run EKM Proxy.

Microsoft calls external key management a last-resort, gated option for organizations with a hard legal or contractual mandate. The preview supports wrap and unwrap only, has no SLA for external keys or the proxy, requires Microsoft account team enablement, and excludes Azure Government and Azure operated by 21Vianet during preview.

## Confidential computing

[Azure confidential computing](https://learn.microsoft.com/azure/azure-sovereign-clouds/public/confidential-computing) protects data in use by running computation inside a hardware-based, attested Trusted Execution Environment. It extends the usual at-rest and in-transit encryption model to data while it is being processed.

For operational sovereignty, confidential computing reduces the need to trust platform operators and privileged software layers. Workloads can use attestation before releasing secrets or processing sensitive data. This concept matters when the customer needs evidence that plaintext data is not visible to cloud operators during processing.

## Sovereign Control Panel

[Sovereign Control Panel](https://learn.microsoft.com/azure/azure-sovereign-clouds/public/sovereign-control-panel) is the current name for Regulated Environment Management. Microsoft Learn states that "Regulated Environment Management (REM) is now Sovereign Control Panel (SCP)."

SCP gives Azure customers one place to discover, control, and act on sovereignty posture:

- Discover posture with evidence across residency, confidentiality, operational sovereignty, and continuity.
- Control required sovereignty rules.
- Act on sovereign risk and remediate resources that drift from the expected state.

SCP combines Azure Policy evaluations with direct resource configuration reads. That matters because sovereignty evidence is not limited to policy aliases.
