Use these questions to check your understanding of RAG fundamentals and the current Foundry Local family.

### Question 1: RAG basics

What does retrieval-augmented generation add to a language model application?

- A) It removes the need for a language model.
- B) It retrieves relevant source content and gives it to the model as context.
- C) It trains the model again for every question.
- D) It stores only keyword indexes and does not use embeddings.

<KnowledgeCheck answer="B" reference="/level-100/module-05-foundry-local/rag-fundamentals/">

B is correct because RAG retrieves source content and adds it to the model prompt. A is wrong because RAG still uses a language model for generation. C is wrong because RAG updates the knowledge source without retraining the model for every query. D is wrong because RAG often uses embeddings and vector search, although keyword search can also be part of the retrieval design.

</KnowledgeCheck>

### Question 2: Chunking

Why do RAG pipelines split documents into chunks?

- A) To make each retrieved item small enough to use as focused model context.
- B) To remove citations from generated answers.
- C) To prevent metadata from being stored.
- D) To make source documents public.

<KnowledgeCheck answer="A" reference="/level-100/module-05-foundry-local/rag-fundamentals/">

A is correct because chunking lets the system retrieve focused passages instead of whole documents. B is wrong because citations depend on preserving source references. C is wrong because useful metadata is usually kept with chunks. D is wrong because chunking does not change the access boundary of the source content.

</KnowledgeCheck>

### Question 3: Rename

What is the current name for the capability formerly called Edge RAG enabled by Azure Arc?

- A) Azure AI Search Local
- B) Agentic Retrieval in Foundry Local
- C) Microsoft 365 Local Search
- D) Azure Arc Data Controller

<KnowledgeCheck answer="B" reference="/level-100/module-05-foundry-local/agentic-retrieval/">

B is correct because the June 2026 Microsoft Learn changelog says Edge RAG enabled by Azure Arc was renamed to Agentic Retrieval. A, C, and D are different names and do not describe the renamed capability.

</KnowledgeCheck>

### Question 4: Preview status

Which statement is correct about Foundry Local on Azure Local and Agentic Retrieval in Foundry Local?

- A) Both are generally available.
- B) Foundry Local is retired, and Agentic Retrieval is generally available.
- C) Both are in preview.
- D) Agentic Retrieval is a legal note only, not a product capability.

<KnowledgeCheck answer="C" reference="/level-100/module-05-foundry-local/foundry-local-overview/">

C is correct because Microsoft Learn marks both Foundry Local on Azure Local and Agentic Retrieval in Foundry Local as preview. A and B are wrong because neither page says both services are generally available. D is wrong because Agentic Retrieval is documented as an Azure Arc-enabled Kubernetes extension, even though the older Transparency Note still uses the Edge RAG name.

</KnowledgeCheck>

### Question 5: Language model endpoint

What changed about language models in the June 2026 Agentic Retrieval release?

- A) Phi-3.5 and Mistral-7B became mandatory bundled models.
- B) Language models were removed from the architecture.
- C) The extension stopped bundling Phi-3.5 and Mistral-7B, and deployments now require a language model endpoint.
- D) Agentic Retrieval can only use a public cloud model.

<KnowledgeCheck answer="C" reference="/level-100/module-05-foundry-local/agentic-retrieval/">

C is correct because the June 2026 release removed bundled Phi-3.5 and Mistral-7B models and requires a language model endpoint. A is the opposite of the documented change. B is wrong because a model endpoint is still required. D is wrong because Foundry Local on Azure Local is the recommended local endpoint, and external Bring Your Own Model endpoints are also supported.

</KnowledgeCheck>

### Question 6: Foundry Local role

What role does Foundry Local on Azure Local usually play with Agentic Retrieval?

- A) It is the recommended local language model endpoint.
- B) It replaces document ingestion and collections.
- C) It is the only chat user interface.
- D) It is a database for storing source documents.

<KnowledgeCheck answer="A" reference="/level-100/module-05-foundry-local/foundry-local-overview/">

A is correct because Agentic Retrieval can use Foundry Local on Azure Local as the recommended local model endpoint. B is wrong because Agentic Retrieval provides ingestion and collections. C is wrong because Agentic Retrieval includes the local chat experience. D is wrong because Foundry Local serves models rather than acting as the RAG knowledge store.

</KnowledgeCheck>

### Question 7: Inference runtimes

Which inference runtimes does Foundry Local on Azure Local support for generative AI serving?

- A) ONNX-GenAI and vLLM
- B) SQL Server and PostgreSQL
- C) Kubernetes Gateway API and Istio
- D) Docling and Calico

<KnowledgeCheck answer="A" reference="/level-100/module-05-foundry-local/foundry-local-overview/">

A is correct because Foundry Local on Azure Local supports the default ONNX-GenAI engine and the vLLM engine. B lists databases. C lists networking components. D mixes a document parser with a networking policy option and does not name the Foundry Local inference runtimes.

</KnowledgeCheck>

### Question 8: Arc extension

Which Azure Arc extension name is associated with Agentic Retrieval?

- A) `microsoft.arc.rag`
- B) `microsoft.arc.sqlmi`
- C) `microsoft.azurelocal.vm`
- D) `microsoft.foundry.search`

<KnowledgeCheck answer="A" reference="/level-100/module-05-foundry-local/agentic-retrieval/">

A is correct because Agentic Retrieval is deployed as the Azure Arc-enabled Kubernetes extension `microsoft.arc.rag`. B is for a different Arc data service. C and D are not the documented Agentic Retrieval extension name.

</KnowledgeCheck>

### Question 9: Deployment modes

Which deployment mode installs the knowledge layer without the agent orchestration layer?

- A) `combined`
- B) `agentic`
- C) `knowledge`
- D) `inference`

<KnowledgeCheck answer="C" reference="/level-100/module-05-foundry-local/agentic-retrieval/">

C is correct because `knowledge` deploys data ingestion and RAG without agents. A deploys the full platform. B deploys agents without local data ingestion. D is not one of the documented Agentic Retrieval deployment modes.

</KnowledgeCheck>

### Question 10: Disconnected sites

Why might a disconnected site evaluate Foundry Local on Azure Local and Agentic Retrieval?

- A) To keep inference and retrieval close to local data when internet connectivity is unavailable.
- B) To avoid all Kubernetes operations.
- C) To send all source documents to a public cloud region.
- D) To remove the need for preview planning.

<KnowledgeCheck answer="A" reference="/level-100/module-05-foundry-local/foundry-local-use-cases/">

A is correct because both services document preview support for disconnected or local operations on Azure Local. B is wrong because both services use Arc-enabled Kubernetes. C is wrong because the local pattern is designed to keep customer content in the local environment. D is wrong because preview services still require preview planning and current documentation review.

</KnowledgeCheck>
