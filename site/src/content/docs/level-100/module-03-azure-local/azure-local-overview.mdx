## What Azure Local is

Azure Local is Microsoft's on-premises infrastructure platform for running virtual machines, Azure Kubernetes Service (AKS) on Azure Local, and selected Azure Arc-enabled services on validated hardware. Microsoft Learn describes hyperconverged Azure Local as a generally available solution that uses Hyper-V, Storage Spaces Direct, Failover Clustering, and core Azure management services on hardware from Microsoft partners ([source](https://learn.microsoft.com/azure/azure-local/overview/hyperconverged-overview?view=azloc-2609)).

Azure Stack HCI became Azure Local in release 2411 in November 2024 ([source](https://learn.microsoft.com/azure/azure-local/previous-releases/whats-new-24?view=azloc-2609#features-and-improvements-in-2411)), and the Azure Stack HCI 23H2 OS reached end of support in April 2026 ([source](https://learn.microsoft.com/azure/azure-local/release-information-23h2?view=azloc-2609#os-version-23h2)).

Azure Local is the infrastructure foundation for [Sovereign Private Cloud](/level-100/module-02-cloud-models/sovereign-private-cloud/). It lets an organization keep workloads and data on-premises while using Azure-consistent management, governance, and lifecycle operations when the environment is connected. In disconnected operations, the selected control plane runs locally instead of depending on Azure public cloud connectivity.

## What it runs

At Level 100, think of Azure Local as three layers:

| Layer | What it includes | Why it matters |
| --- | --- | --- |
| Hardware | Microsoft partner hardware from the Azure Local catalog. | The platform depends on validated hardware, drivers, firmware, and support paths. |
| Platform | Hyper-V, Storage Spaces Direct, Failover Clustering, software-defined networking, and update orchestration. | These components provide local compute, storage, resiliency, and lifecycle management. |
| Workloads | Azure Local VMs enabled by Azure Arc, AKS on Azure Local, SQL Server, Microsoft 365 Local, Foundry Local, and other supported workloads. | Workload support varies by deployment type and connectivity mode. |

Azure Local VMs enabled by Azure Arc provide VM lifecycle management through Azure, including start, stop, pause, memory and vCPU changes, and disk or network interface changes ([source](https://learn.microsoft.com/azure/azure-local/concepts/compare-vm-management-capabilities?view=azloc-2609)). AKS on Azure Local provides Kubernetes for containerized workloads on Azure Local. Under disconnected operations, AKS on Azure Local and Arc-enabled Kubernetes are still preview features ([source](https://learn.microsoft.com/azure/azure-local/manage/disconnected-operations-overview?view=azloc-2609#supported-services)).

## Release train and support window

Azure Local now follows a monthly release train with versions such as 2607, 2608, and 2609. Microsoft Learn notes that the versioning model changed from annual releases to monthly trains such as 2507 and 2506 ([source](https://learn.microsoft.com/azure/azure-local/release-information-23h2?view=azloc-2609#about-azure-local-releases)).

Systems must stay within six months of the most recent Azure Local release to remain supported under the Modern Lifecycle Policy ([source](https://learn.microsoft.com/azure/azure-local/update/about-updates-23h2?view=azloc-2609#lifecycle-cadence)). This support window is a planning requirement, not just an update preference. If a sovereign environment delays updates, the operations team still needs a documented path to keep the platform supported.

Microsoft also notes that Azure Arc resource bridge requires solution updates within one year to keep certificates valid and Azure Local VM functionality working ([source](https://learn.microsoft.com/azure/azure-local/update/about-updates-23h2?view=azloc-2609#lifecycle-cadence)). For L100 planning, remember two windows. Azure Local releases have a six-month support window, and the Arc resource bridge has a one-year certificate-related update requirement.

## Connected and disconnected choices

Azure Local supports two connectivity models:

| Connectivity model | What it means |
| --- | --- |
| Connected operations | Azure Local keeps periodic connectivity to Azure for control plane activities such as monitoring, governance, lifecycle management, and portal-based operations. Running workloads stay on-premises. |
| Disconnected operations | Azure Local uses a local control plane for selected Azure experiences when the environment cannot connect to Azure public cloud. |

Connected deployments tolerate intermittent disconnections of up to 30 days without impacting running workloads ([source](https://learn.microsoft.com/azure/azure-sovereign-clouds/private/azure-local/connected-operations-overview#what-does-connected-mean)). That statement does not make a connected deployment the same as disconnected operations. Disconnected operations have a separate local control plane, eligibility requirements, and management cluster design.

Disconnected operations require Azure Local 2602 or later ([source](https://learn.microsoft.com/azure/azure-local/manage/disconnected-operations-overview?view=azloc-2609)). The February 2026 Microsoft blog also announced "Azure Local disconnected operations (now available)" ([source](https://blogs.microsoft.com/blog/2026/02/24/microsoft-sovereign-cloud-adds-governance-productivity-and-support-for-large-ai-models-securely-running-even-when-completely-disconnected/)).

## Licensing and billing

Azure Local is priced per physical core on on-premises machines, with extra consumption-based charges for Azure services that you use. Charges roll up to the existing Azure subscription ([source](https://learn.microsoft.com/azure/azure-local/overview/hyperconverged-overview?view=azloc-2609#benefits)).

Azure Hybrid Benefit can waive the Azure Local host service fee when you exchange one Software Assurance-enabled Windows Server Datacenter core for one physical Azure Local core. The benefit is limited to hyperconverged, cloud-connected deployments with no external storage. Azure Local L2 and L3 external-storage deployments are not supported for that benefit ([source](https://learn.microsoft.com/azure/azure-local/concepts/azure-hybrid-benefit?view=azloc-2609#what-is-azure-hybrid-benefit-for-azure-local)).

An OEM license is another option. The OEM license is sold with Azure Local hardware, remains valid for the hardware lifetime, covers up to 16 cores with add-ons for larger systems, and includes Azure Local, Windows Server Datacenter guest VMs, and AKS enabled by Azure Arc ([source](https://learn.microsoft.com/azure/azure-local/oem-license?view=azloc-2609#about-the-oem-license)).
