### Question 1: Product role

What is Azure Local's role in Sovereign Private Cloud?

- A) It provides on-premises infrastructure for VMs, AKS on Azure Local, and selected Arc-enabled services.
- B) It replaces Azure Arc for all hybrid management.
- C) It is only a public cloud region for sovereign workloads.
- D) It is only the name for disconnected deployments.

<KnowledgeCheck answer="A" reference="/level-100/module-03-azure-local/azure-local-overview/">

A is correct because Azure Local runs on-premises infrastructure for VMs, AKS on Azure Local, and selected Arc-enabled services. B is wrong because Azure Arc remains the management bridge. C is wrong because Azure Local runs on customer-operated hardware, not as a public cloud region. D is wrong because Azure Local covers connected and disconnected operating models.

</KnowledgeCheck>

### Question 2: Release support

How current must Azure Local stay to remain supported under the current lifecycle guidance?

- A) Within 30 days of the latest release.
- B) Within six months of the most recent release.
- C) Within one year of the latest release, with no other conditions.
- D) Only major annual versions need updates.

<KnowledgeCheck answer="B" reference="/level-100/module-03-azure-local/azure-local-overview/">

B is correct because Azure Local must stay within six months of the most recent release. A confuses the connected-operations connectivity tolerance with update support. C confuses the Arc resource bridge one-year update requirement with the Azure Local support window. D is wrong because Azure Local now follows monthly release trains.

</KnowledgeCheck>

### Question 3: Deployment type limits

Which deployment type and scale pairing is correct?

- A) Hyperconverged deployments support 1 to 16 machines.
- B) Disaggregated deployments support up to 16 machines.
- C) Multi-rack deployments support up to 64 nodes per instance.
- D) Small form factor is the deployment type for every disconnected environment.

<KnowledgeCheck answer="A" reference="/level-100/module-03-azure-local/azure-local-architecture/">

A is correct because hyperconverged deployments support one to 16 machines. B is wrong because disaggregated deployments support up to 64 machines. C is wrong because multi-rack deployments scale up to 128 nodes per instance. D is wrong because small form factor is a connected deployment type in the current deployment guide, while disconnected operations apply to hyperconverged and disaggregated paths.

</KnowledgeCheck>

### Question 4: Fleet scale

What does "thousands of nodes" mean in current Azure Local sovereignty content?

- A) A single hyperconverged Azure Local instance can have thousands of machines.
- B) A single disaggregated Azure Local instance can have thousands of machines.
- C) A single multi-rack Azure Local instance can have thousands of nodes.
- D) A sovereign environment can contain many Azure Local instances that add up to thousands of servers.

<KnowledgeCheck answer="D" reference="/level-100/module-03-azure-local/azure-local-architecture/">

D is correct because the thousands wording describes fleet scale across a sovereign environment. A is wrong because hyperconverged is limited to 16 machines. B is wrong because disaggregated is limited to 64 machines. C is wrong because multi-rack is limited to 128 nodes per instance.

</KnowledgeCheck>

### Question 5: Connected operations

In connected operations, what happens if Azure connectivity is temporarily lost?

- A) Running workloads can continue for intermittent disconnections up to 30 days.
- B) All VMs shut down immediately.
- C) The deployment automatically becomes disconnected operations.
- D) Azure Local no longer requires updates.

<KnowledgeCheck answer="A" reference="/level-100/module-03-azure-local/azure-local-connected-mode/">

A is correct because connected operations support intermittent disconnections up to 30 days without impacting running workloads. B is wrong because workload execution stays local. C is wrong because disconnected operations are a separate mode with a local control plane and eligibility requirements. D is wrong because the release support window still applies.

</KnowledgeCheck>

### Question 6: Disconnected status

Which statement correctly describes disconnected operations?

- A) Disconnected operations are preview for Azure Local 2602 or later.
- B) Disconnected operations are generally available for Azure Local 2602 or later, but AKS under disconnected operations is preview.
- C) Disconnected operations work only with multi-rack deployments.
- D) Disconnected operations need no special hardware planning.

<KnowledgeCheck answer="B" reference="/level-100/module-03-azure-local/azure-local-disconnected-mode/">

B is correct because disconnected operations are available for Azure Local 2602 or later, while AKS on Azure Local with disconnected operations is preview. A is wrong because the platform feature is now available. C is wrong because disconnected operations are supported for hyperconverged and disaggregated paths, not multi-rack. D is wrong because a dedicated management cluster and supported Premier hardware are required.

</KnowledgeCheck>

### Question 7: Management cluster

What is the production management cluster requirement for disconnected operations?

- A) One shared workload node can host the local control plane.
- B) A dedicated three-node Azure Local management cluster hosts the local control plane.
- C) A public Azure region hosts the control plane.
- D) Any unmanaged virtualization cluster can host the control plane.

<KnowledgeCheck answer="B" reference="/level-100/module-03-azure-local/azure-local-disconnected-mode/">

B is correct because production disconnected operations require a dedicated three-node Azure Local management cluster. A is wrong because tenant workloads must run on separate workload clusters. C is wrong because disconnected operations replace selected Azure public cloud control plane functions with a local control plane. D is wrong because supported Azure Local hardware and configurations are required.

</KnowledgeCheck>

### Question 8: Hardware categories

Which set lists the current Azure Local hardware catalog categories?

- A) Basic, Standard, and Premium.
- B) Bronze, Silver, and Gold.
- C) Validated Nodes, Integrated Systems, and Premier Solutions.
- D) Developer, Production, and Air-gapped.

<KnowledgeCheck answer="C" reference="/level-100/module-03-azure-local/azure-local-hardware/">

C is correct because the current catalog categories are Validated Nodes, Integrated Systems, and Premier Solutions. A and B are not Azure Local hardware catalog categories. D mixes lifecycle and operating ideas rather than catalog categories.

</KnowledgeCheck>

### Question 9: Billing and benefits

Which statement about Azure Local billing is correct?

- A) Azure Local is billed per physical core through the Azure subscription unless a benefit or OEM license changes the billing treatment.
- B) Azure Hybrid Benefit applies to every Azure Local deployment type.
- C) OEM licensing is bought directly from Azure Marketplace without hardware.
- D) Azure Local has no billing relationship with Azure subscriptions.

<KnowledgeCheck answer="A" reference="/level-100/module-03-azure-local/azure-local-overview/">

A is correct because Azure Local is priced per physical core on on-premises machines and charges roll up to the Azure subscription. B is wrong because Azure Hybrid Benefit is limited to hyperconverged, cloud-connected deployments with no external storage. C is wrong because the OEM license is sold with Azure Local hardware through hardware partners. D is wrong because Azure subscription billing is the standard model.

</KnowledgeCheck>

### Question 10: VM management

Which VM type has Azure lifecycle management such as start, stop, vCPU changes, memory changes, and disk or network interface changes?

- A) Azure Local VMs enabled by Azure Arc.
- B) Unmanaged VMs created only with local tools.
- C) Any VM with no Azure Connected Machine agent.
- D) Arc-enabled servers converted into Azure Local VMs.

<KnowledgeCheck answer="A" reference="/level-100/module-03-azure-local/azure-local-architecture/">

A is correct because Azure Local VMs enabled by Azure Arc have lifecycle management through Azure Arc resource bridge. B and C are wrong because unmanaged VMs do not have Azure management. D is wrong because Microsoft Learn says conversion from an Arc-enabled server or unmanaged VM to an Azure Local VM is not supported.

</KnowledgeCheck>
