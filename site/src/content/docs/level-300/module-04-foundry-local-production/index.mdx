[Foundry Local on Azure Local is in preview](https://learn.microsoft.com/azure/azure-sovereign-clouds/private/foundry-local/overview). It serves AI models on an Arc-enabled Kubernetes cluster that runs on Azure Local. [Agentic Retrieval in Foundry Local is also in preview](https://learn.microsoft.com/azure/azure-arc/agents-tools-foundry-local/overview). Agentic Retrieval (formerly Edge RAG) uses a Foundry Local on Azure Local endpoint as the recommended local language model endpoint.

This module replaces the old production content for Agentic Retrieval (formerly Edge RAG) with the current Foundry Local family. You plan a production inference platform first, then connect Agentic Retrieval as a consuming workload. The design center is no longer a bundled RAG stack. It is a Kubernetes inference platform with model deployments, Gateway API routing, local model caching, evaluation jobs, and disconnected deployment paths.

## How to read this module

Read the architecture page first if you own platform design. It maps Azure Local, AKS Arc, Azure Arc extensions, Gateway API, authentication, GPU pools, and Agentic Retrieval into one production shape. Read the performance page when you need to select a runtime, model, context window, or GPU topology. Read the lifecycle page when you need to prove how model catalog sync, caching, deployment, evaluation, and disconnected transfer work.

The production decision is where to put responsibility. Foundry Local on Azure Local owns model serving. Agentic Retrieval owns ingestion, vector search, agents, tools, and chat. Keeping those responsibilities separate helps you size GPUs, secure endpoints, and update models without assuming the RAG layer and inference layer scale the same way.
